Return two top-level arrays in the same response.

- problems: Every distinct, meaningful gap identified during the review. Each problem must be concise and independently reviewable by a business user.
- findings: The corresponding detailed corrective action for each identified problem. Every finding must reference its problem_id.

Use this exact top-level structure:

{
  "overall_assessment": "adequate | gaps_identified | clarification_required",
  "problems": [
    {
      "problem_id": "P001",
      "problem": "Specific gap or inconsistency, maximum 160 characters.",
      "business_rationale": "Why it matters, maximum 200 characters.",
      "proposed_flow": "Recommended actor/action sequence or capability, maximum 160 characters."
    }
  ],
  "findings": [
    {
      "problem_id": "P001",
      "target_path": "Exact JSON path or null",
      "correction_type": "ADD | UPDATE | REMOVE | NO_CHANGE",
      "proposed_content": {},
      "placement_instruction": "Precise insertion, update, removal, or clarification instructions.",
      "review_action": "recommended_change | business_clarification",
      "confidence": "high | medium | low"
    }
  ]
}

## OUTPUT RULES

1. Populate problems with every distinct, meaningful gap identified during the review.
2. Populate findings with the corresponding corrective action, using the exact matching problem_id.
3. Keep each problem independently reviewable so the business user can reject individual findings without rejecting unrelated findings.
4. Every problem must have exactly one finding. Do not omit a meaningful problem merely because its correction is uncertain.
5. For a material uncertainty, retain the problem and create a NO_CHANGE finding with business_clarification. Do not invent corrective content.
6. For ADD, provide only the new JSON fragment.
7. For UPDATE, provide only the minimal replacement value or object fragment.
8. For REMOVE, identify the exact element to remove and explain why in placement_instruction.
9. For NO_CHANGE, use an empty proposed_content object and explain the required business decision in placement_instruction.
10. If the exact correction path cannot be established, set target_path to null and describe the closest verifiable location in placement_instruction.
11. Do not add undeclared fields to problems or findings.
12. Do not regenerate the original artifact or apply corrections automatically.
13. If no material issues or clarification requirements are identified, return:
{
  "overall_assessment": "adequate",
  "problems": [],
  "findings": []
}
14. If there are material gaps and no unresolved clarification is needed, use "gaps_identified".
15. If a material business clarification is required, use "clarification_required". This may coexist with other actionable findings.
